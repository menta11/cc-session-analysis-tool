# AI 追问终端链路 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 AI 分析报告之上，加"打开 claude 终端继续追问"按钮——把每次分析产生的 claude 会话 id 接出来，点击即在 OS 终端 `claude --resume <id>` 续接，按会话记忆报告状态避免串台。

**Architecture:** 纯函数 `buildResumeCommand(id, cwd, platform)` 构造跨平台续问命令（Win `cmd /c start` / Mac `osascript`），薄封装 `openTerminal` 经 `terminal:open` IPC 由渲染层调用；`App.tsx` 报告状态由全局单值改为 `Record<selectedPath, ReportState>`，续问按钮禁用判据为 `!claudeId`。

**Tech Stack:** Electron 31 + React 18 + TypeScript（strict，noUnusedLocals），Vitest（node 环境，仅 core/纯函数可测，无 React 测试基建）。

## Global Constraints

- 项目**非 git 仓库**：任务以"测试/类型检查通过"为收口，不写 commit 步骤。
- `npm run typecheck` = `tsc --noEmit -p tsconfig.node.json && tsc --noEmit -p tsconfig.web.json`；`npm test` = `vitest run`。
- `tsconfig.node.json` 覆盖 `electron/**/*.ts`；`noUnusedLocals`/`noUnusedParameters` 为真——不得留未用导入/参数。
- 目标平台仅 **Win + Mac**（方案 §1）；linux 不在范围。
- `sessionId` 接口契约：`analyze:run` 返回的 `ClaudeResult` 含 `sessionId?: string`（成功且 stream-json 可用时非空、降级时 undefined）。Task 2-4 据此 gating。
- **Task 3、4 依赖"AI 分析报告链路"stream-json 改造落地**（`runClaudeStream` 透出 `sessionId`、`AiReport` 改 markdown 渲染）。Task 1、2 不依赖，可立即动手。

- [ ] **Step 3: 写最小实现**

Create `electron/main/terminal.ts`（**仅纯函数，不引 node:child_process**，保证 vitest 可导入）:

```ts
const UUID = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i

/** 校验 claude sessionId 是否为合法 UUID（开终端前的注入守卫）。 */
export function isSessionId(v: string): boolean {
  return UUID.test(v)
}

export interface ResumeCommand {
  exe: string
  args: string[]
  opts: { detached: boolean; stdio: 'ignore' }
}

/** 转义 AppleScript 字符串字面量里的反斜杠与双引号。 */
function escAppleScript(s: string): string {
  return s.replace(/\\/g, '\\\\').replace(/"/g, '\\"')
}

/**
 * 构造跨平台续问命令：在 OS 终端跑 `claude --resume <id>`，cwd 设到被分析会话的工作目录。
 * id 须为 UUID（由调用方 openTerminal 校验）；cwd 须存在（由调用方兜底）。
 */
export function buildResumeCommand(id: string, cwd: string, platform: NodeJS.Platform): ResumeCommand {
  const opts = { detached: true, stdio: 'ignore' as const }
  if (platform === 'win32') {
    // start ""  = 空 title，规避 start 把首参数当程序名；/d <cwd> 设新窗口工作目录；cmd /k 跑完不关窗
    return {
      exe: 'cmd.exe',
      args: ['/d', '/c', 'start', '', '/d', cwd, 'cmd', '/k', `claude --resume ${id}`],
      opts,
    }
  }
  // darwin（及其它 *nix 回退到 osascript；本方案仅支持 win/mac）
  const script = `tell application "Terminal" to do script "cd \\"${escAppleScript(cwd)}\\" && claude --resume ${id}"`
  return { exe: 'osascript', args: ['-e', script], opts }
}
```

末尾追加：

```ts
/**
 * 在 OS 终端打开 `claude --resume <id>` 续接分析对话。
 * - id 非 UUID → 拒绝、不开窗。
 * - cwd 为空/不存在 → 退到用户 home。
 * - detached + unref：终端与主进程脱钩，关 app 不杀终端。
 * 不等终端退出，立即返回 ok；终端自身成败由用户在窗口里观察。
 */
export async function openTerminal(
  id: string,
  cwd: string | null,
): Promise<{ ok: boolean; error?: string }> {
  if (!isSessionId(id)) return { ok: false, error: 'sessionId 非法，拒绝打开终端' }
  const { app } = await import('electron')
  const dir = cwd && existsSync(cwd) ? cwd : app.getPath('home')
  const cmd = buildResumeCommand(id, dir, process.platform)
  const child = spawn(cmd.exe, cmd.args, { ...cmd.opts, cwd: dir })
  child.on('error', () => {
    /* 终端启动失败仅记日志，不抛；用户已在窗口侧观察 */
  })
  child.unref()
  return { ok: true }
}
```

## 实现后修订（2026-07-31，对齐真实代码）

计划已全部执行。实现中相对原计划步骤的偏差：

1. **Task 2 `openTerminal` 签名**：原计划 `openTerminal(id, cwd)` + `await import('electron')` + `existsSync` 兜底 home。实际改为 `openTerminal(id)` —— **不接收 cwd**、不依赖 electron、不 import fs，cwd 直接取 `process.cwd()`。原因见下条。
2. **续问 cwd 用 `process.cwd()` 而非 `session.cwd`**：原计划 Task 3 的 `onOpenTerminal` 传 `session?.cwd`。实测 `claude --resume <id>` 报 "No conversation found"——因 claude 按 `sanitize(cwd)` 存会话，分析时 `runClaudeStream` 的 spawn 未指定 cwd（用主进程 cwd），会话落在 `~/.claude/projects/D--project-cc-session-analysis-tool/`；而 `session.cwd` 指向被分析会话的项目（`D--workspace-process-docs`），sanitize 后路径不同 → 找不到。修：续问与分析同 cwd = `process.cwd()`。连带 IPC/preload/preload.d.ts/App 的 `openTerminal` 全部去掉 cwd 参数。
3. **Task 3 App 状态**：原计划换 3 个单值（text/loading/error）。实际另一终端已把 `sessionId` 也存为单值 state，故换 **4 个** → `Record<selectedPath, ReportState>`（ReportState 含 `claudeId`）。`cur.claudeId` 作为 `sessionId` prop 传 AiReport（沿用其 prop 名，不另起 `claudeId`）。
4. **Task 4 AiReport**：原计划新增 `claudeId` prop。实际另一终端的 AiReport 已有 `sessionId` prop + chip，故**沿用 `sessionId`**，仅加 `onOpenTerminal` prop + 按钮。另补 `btnStyle(disabled)` 显式禁用样式（`opacity:0.5 + cursor:not-allowed`）——否则自定义 background 盖掉浏览器默认禁用灰，按钮未分析时看着像能点。
5. **analyze:run 超时**：原计划未涉及。实测大会话（71598b9d，1572 条/90 子 agent）厚摘要+取证易超 180s 默认值。`index.ts` 的 `analyze:run` 调 `runClaudeStream(..., { timeoutMs: 600_000 })` 放宽到 10 分钟。
6. **测试**：原计划 Task 1 仅 `buildResumeCommand`/`isSessionId`。实际增 `openTerminal('not-a-uuid')` 守卫测试（非法 id 早返回不 spawn，安全可测）。共 6 测。
